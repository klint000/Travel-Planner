# Travel Planner

## Цель доработки
В проекте реализовано разграничение прав доступа между ролями `User`, `Manager`, `Admin`, добавлена административная панель и условная видимость элементов интерфейса.

## Реализовано
- Авторизация с сохранением текущего пользователя и его роли.
- Блокировка пользователя через поле `users.is_blocked`.
- Ролевой доступ на странице каталога:
  - `User` — только просмотр карточек.
  - `Manager` — просмотр + CRUD (`Добавить`, `Редактировать`, `Удалить`).
  - `Admin` — всё как у `Manager` + кнопка `Админ-панель`.
- Админ-панель (`AdminPanelPage`) только для роли `Admin`:
  - вкладка `Управление пользователями`: список, поиск, смена роли, блок/разблок;
  - вкладка `Системная аналитика`: сводные метрики по поездкам и пользователям.
- Кнопка `Выйти`: завершение сессии и возврат на `LoginPage`.

## Инструкция по тестированию ролей
1. Запустите приложение.
2. Войдите под существующим пользователем из БД (`users`) или зарегистрируйте нового.
3. При необходимости задайте роль в БД по `users.role_id`:
   - `1` = `User`
   - `2` = `Manager`
   - `3` = `Admin`
4. Проверьте поведение `CatalogPage` под каждой ролью:
   - `User`: кнопки CRUD скрыты, доступен только просмотр карточек.
   - `Manager`: видны кнопки CRUD, операции добавления/редактирования/удаления выполняются.
   - `Admin`: видны CRUD + кнопка `Админ-панель`.
5. Для `Admin` откройте `Админ-панель` и проверьте:
   - вкладка `Управление пользователями`:
     - отображение таблицы пользователей;
     - поиск по ФИО/Email;
     - смену роли выбранного пользователя;
     - блокировку/разблокировку.
   - вкладка `Системная аналитика`:
     - общее количество записей;
     - количество записей по категориям;
     - топ-5 записей;
     - статистику пользователей по ролям.
6. Нажмите `Выйти` и убедитесь, что происходит возврат на страницу входа.
7. Попробуйте войти под заблокированным пользователем: вход должен быть запрещен.
